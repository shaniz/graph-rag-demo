CPU Saturation (Child of Infrastructure)

CPU saturation causes request queuing and increased latency across all services. Parent node: Infrastructure Performance Issues. No child nodes — this is a leaf. Diagnose: 'mpstat -P ALL 1' shows per-core utilization — uneven distribution indicates single-threaded bottleneck. 'perf top' shows hot kernel and userspace functions. 'pidstat 1' shows per-process CPU over time. Common causes: (1) Single-threaded application — scale horizontally with multiple processes behind a load balancer; use Node.js cluster module or Gunicorn workers for Python. (2) GC pressure in JVM — use G1GC with -XX:+UseG1GC; monitor with 'jstat -gcutil <pid> 1000'; tune heap size. (3) Busy-wait polling loops — replace with event-driven I/O using epoll/kqueue. (4) Crypto operations on hot path — offload TLS termination to a reverse proxy (Nginx, HAProxy) or hardware accelerator. (5) Runaway process — use cgroups (systemd CPUQuota=50%) to cap CPU consumption per service.
