Database Bottlenecks (Child of Backend)

Database slowness is the most common backend performance problem. Parent node: Backend Performance Issues. No child nodes — this is a leaf. Diagnose: enable slow query logging in PostgreSQL (log_min_duration_statement = 500) or MySQL (slow_query_log = ON, long_query_time = 0.5). Review execution plans with EXPLAIN ANALYZE in PostgreSQL or EXPLAIN in MySQL. Common causes: (1) Missing indexes — add indexes on columns used in WHERE, JOIN ON, and ORDER BY clauses; use 'pg_stat_user_indexes' to find unused indexes to remove. (2) Lock contention — long-running transactions block others; use 'SELECT * FROM pg_locks JOIN pg_stat_activity' to identify blocking sessions; kill with pg_terminate_backend(pid). (3) Unbounded result sets — add LIMIT clauses; paginate large result sets with cursor-based pagination. (4) Cartesian joins — always verify JOIN conditions; use EXPLAIN to check for seq scans on large tables. (5) Vacuum lag in PostgreSQL — dead tuples accumulate if autovacuum can't keep up; run VACUUM ANALYZE manually or tune autovacuum_vacuum_scale_factor.
