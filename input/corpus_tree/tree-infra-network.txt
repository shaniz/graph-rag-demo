Network Latency and Throughput Issues (Child of Infrastructure)

Network problems cause slow connections and request timeouts. Parent node: Infrastructure Performance Issues. No child nodes — this is a leaf. Diagnose: 'ping -c 100 target' measures round-trip latency and packet loss; any loss above 0.1% is significant. 'mtr --report target' identifies which hop introduces latency. 'iperf3 -c server' measures TCP throughput. 'ss -s' shows socket statistics and connection counts. Common causes: (1) Bandwidth saturation — use 'iftop' to identify which process or IP consumes bandwidth; implement traffic shaping with 'tc qdisc'. (2) High connection count — tune kernel parameters: net.core.somaxconn, net.ipv4.tcp_max_syn_backlog, net.ipv4.ip_local_port_range. (3) DNS resolution latency — cache DNS locally with systemd-resolved or dnsmasq; check TTLs. (4) MTU mismatch causing fragmentation — test with 'ping -M do -s 1472 gateway'; set MTU appropriately on interface. (5) Network card interrupt coalescing — tune with 'ethtool -C eth0 rx-usecs 50' to balance latency vs throughput.
