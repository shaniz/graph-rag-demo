Disk I/O Bottlenecks (Child of Infrastructure)

Disk I/O bottlenecks cause high latency for any workload that reads or writes files. Parent node: Infrastructure Performance Issues. No child nodes — this is a leaf. Diagnose: 'iostat -x 1' — watch %util (saturation above 80%), await (average request time; >10ms for SSD or >50ms for HDD is concerning), and r/s+w/s (IOPS). 'iotop -o' shows which processes are doing I/O. 'blktrace /dev/sda' gives low-level I/O event tracing. Common causes: (1) Insufficient IOPS — upgrade from HDD to NVMe SSD; provision IOPS in cloud (AWS EBS gp3 allows 16,000 IOPS). (2) Write amplification — batch small writes; use write-back caching with appropriate durability guarantees. (3) Filesystem choice — ext4 with relatime mount option reduces metadata writes; XFS performs better for large files and parallel I/O. (4) Log files filling disk — implement log rotation with logrotate; monitor disk usage with 'df -h' and alert at 85%. (5) Swap thrashing — check 'vmstat 1' for high 'si'/'so' (swap in/out); add RAM or reduce memory footprint to eliminate swapping.
