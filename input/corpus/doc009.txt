Kubernetes Pod CrashLoopBackOff Resolution

CrashLoopBackOff in Kubernetes indicates a pod repeatedly failing to start. Investigate with 'kubectl logs <pod-name> --previous' to see logs from the crashed container. 'kubectl describe pod <pod-name>' shows events and error messages. OOMKilled status means the container exceeded memory limits - increase limits in the deployment spec. Exit code 1 is a general application error - check application logs. Exit code 137 indicates SIGKILL (usually OOM). Exit code 139 is a segmentation fault. Check liveness probe configuration - overly aggressive probes kill healthy containers. Verify image pull credentials with 'kubectl get events'. ConfigMap or Secret mounting errors prevent startup - verify names and keys. Init container failures block main container start. Resource limits too low prevent scheduling. Use 'kubectl exec -it <pod> -- /bin/sh' to debug running containers.
